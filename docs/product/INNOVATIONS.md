# 侧笺 · SideTask：项目创新点与产品价值

整理日期：2026-09-25。依据：已合并的产品源码 `6d32d6c`、通过双平台 CI 的检查头 `a1b30d6`，以及仓库内的需求、源码和验收记录。当前为功能完善与内部试用阶段，实际交付状态见 [STATUS](../delivery/STATUS.md)。

侧笺的核心设计，是把任务管理放到学习和工作现场：需要时在屏幕边缘看一眼、记一项、勾一下，需要集中整理时再进入完整控制台。创新价值集中在这套连续的使用流程，以及支撑它的任务语义、窗口协作和草稿保护。

本文所说的“创新点”指本项目的产品设计与工程整合特点。已有桌面工具提供快捷面板、本地存储和主题切换等能力；本文不作行业首创或专利新颖性判断，也不以技术栈名称证明创新。设计参考和取舍保留在[同类调研](../research/ALTERNATIVES.md)、[窗口模式参考](../research/WINDOW_PATTERNS.md)与 [ADR-0002](../decisions/0002-console-and-edge-panel.md)。

## 六项值得重点介绍的特点

| 特点 | 解决的使用问题 | 设计价值 |
| --- | --- | --- |
| 双窗口分工，任务操作贴近当前桌面 | 只想看一项任务，也要进入完整管理界面 | 把高频查看、添加和完成放进边缘小窗，复杂管理留在控制台 |
| 今日安排与截止日期分开表达、同源联动 | “今天做”和“今天截止”混在一起，或同一任务被重复维护 | 一条任务同时支持行动安排和截止约束，完成状态只维护一次 |
| 小窗直接捕捉任务，草稿贯穿操作过程 | 临时想到的事需要跳转页面，切换窗口后又要重新输入 | 就地创建并加入今日，连续添加；失败和普通隐藏保留输入 |
| 展开方式可选，查看与输入分别处理 | 路过边缘误弹出，或查看任务打断原来的输入 | 默认明确单击，可选悬停；结合焦点、固定与交互保护控制窗口行为 |
| 外观可变，任务和编辑上下文保持连续 | 换风格、调布局影响数据或打断正在编辑的内容 | 四套风格与浅深色独立，大小窗同步，偏好变化保留任务和其他草稿 |
| 本地统一状态与可恢复操作 | 多窗口改同一任务产生覆盖，误删或恢复影响其他设置 | 统一提交、版本冲突保护、回收站及备份恢复共同支撑日常使用 |

前四项构成主要的产品与交互特点；后两项增强个性化与可靠性。它们组合起来形成侧笺的使用方式，各项基础机制本身并非新发明。

## 1. 把高频操作放到屏幕边缘

侧笺同时提供边缘小窗与完整控制台。小窗上方展示今日计划，下方展示 DDL，承担查看、快速新增、完成和撤销；控制台承担全量任务管理、完整编辑、搜索、回收站和设置。两者使用同一任务服务和数据库。

例如，用户在阅读课程资料时，可以展开小窗确认下一项任务，完成后直接勾选，再回到资料；需要修改详细备注和截止时间时，再进入控制台。关闭控制台后，小窗和菜单栏／托盘入口仍可继续使用。

这里的价值来自操作分工：小窗保留完成日常动作所需的信息与入口，控制台容纳完整管理能力。第一版只管理独立任务，没有任务树、子任务或部分完成百分比，避免把复杂结构带进小窗。

## 2. 同时回答“今天做什么”和“什么时候必须做完”

今日计划表示行动安排，DDL 表示截止约束。两种视图引用同一个 Task ID；加入今日只建立计划引用，完成或撤销只更新任务主记录。

以“9 月 30 日提交课程报告”为例：9 月 25 日加入今日，不会把截止日期改成 9 月 25 日；当天移出今日，任务和原 DDL 都保留。整项报告完成后，在任一入口勾选，其他视图同步更新。若当天只做了一部分，应保持未完成，不把“今天推进了一点”当作整项完成。

这套区分延伸到时间与排序：

- 今日计划有自己的手动顺序；DDL 可按截止时间或重要程度排序，二者互不改写。
- 仅日期的 DDL 到所选日期结束后才逾期；精确时刻的 DDL 从对应时刻起逾期。
- 跨天不自动删除未完成任务、不自动复制到今日、不修改 DDL。符合条件的旧计划任务进入“此前未完成”组，由用户重新安排。

产品价值是让安排具有弹性，同时保持截止约束清楚、可追溯；不需要通过复制任务或修改截止日来调整今天的计划。

## 3. 从临时想到，到保存成功，保持一条连续路径

今日计划标题旁的“＋”直接打开小窗内输入框，输入名称即可创建任务并加入今日，不必打开控制台。新任务默认普通重要程度、不设 DDL；创建任务和建立今日引用通过一次提交完成。保存后输入框可继续添加下一项。

快速输入同时考虑未完成动作：空白名称不提交，中文输入法组合期间的回车不当作添加；保存失败保留文字，并显示可重试的错误。普通隐藏后重新展开保留草稿，显式关闭输入或退出时再处理未保存内容。

当小窗和控制台同时有草稿，退出按小窗、控制台的顺序确认；任一处取消或保存失败，应用继续运行。这使“快速”覆盖从输入到退出的全过程，而不只是减少一次打开页面的操作。

**边界：**快速输入草稿保存在窗口内存，不是已持久化任务；不承诺强制结束进程、崩溃或断电后恢复未保存文字。Windows 输入时外点隐藏的行为尚未与 Mac 对齐，见下节。

## 4. 用户决定怎样展开，系统区分查看与输入

默认模式是单击把手展开，目标行为是点击外部收起；悬停展开由用户主动选择，只有该模式显示展开与收起延迟。固定展开暂停自动收起，拖动、缩放和退出确认有独立保护。

查看与输入采用不同的焦点处理：悬停查看走非激活路径；明确输入、操作需要键盘控制的控件或处理退出确认时，按需请求焦点。Windows 当前单击展开也会激活小窗。控制台编辑、小窗输入、窗口隐藏和原应用点击需要协调处理，不能把“窗口没有焦点”简单等同于“用户要求收起”。

小窗还支持沿边移动、主动换边或换屏后重新停靠。停靠后的显示和缩放按当前屏幕工作区约束；收起使用真正隐藏窗口的方式。固定展开仍允许移动，便于用户按手头内容调整位置。

**当前平台差异：**Mac 已接入真实鼠标外点事件和隐藏保草稿路径；跨应用实体鼠标及完整原生矩阵仍需补验。Windows 当前仍通过失焦触发收起，且输入期间外点会保持可见，因此不能称两平台的外点语义已经一致。多屏、混合 DPI、拔插、睡眠与 Spaces／虚拟桌面也未完成全部实机验收。

## 5. 个性化不打断当前工作

纸笺、霜序、暖刊、极简四套风格，在字体、密度、色彩、边界和控件形态上有所区别；每套都支持浅色、深色和跟随系统。它们共享任务结构与操作，不引入不同版本的任务库。

风格切换同步控制台、小窗和把手，保留任务、今日计划和其他未保存的设置草稿；外观变化不触发原生窗口重建或显隐切换。窗口尺寸、位置和分区比例则作为使用偏好管理。

这项设计的价值是让用户调整“怎么看”，同时保持“正在做什么”的连续性。四套皮肤本身属于常见功能，值得强调的是它与双窗口一致性、编辑保护和本机偏好的结合。

## 6. 用统一状态和恢复能力支撑轻量体验

大小窗的写入进入同一个 Rust 任务服务，再由 Repository 保存到 SQLite。当前实现保存 JSON 快照，并使用快照与任务修订号检查旧数据；不是已经完成规范化关系表的架构。写入成功后再发布已提交状态，冲突时保留草稿供用户确认，避免旧窗口静默覆盖新结果。

任务误删后可从回收站单项恢复，保留原 Task ID、DDL、完成状态和全部日期的计划，不自动安排到今天。便携备份包含任务、计划和回收站记录，恢复前校验并创建安全备份；设备窗口位置和界面偏好留在本机。数据库升级也有版本与升级前备份，启动恢复有独立入口。

本地存储、无账号的核心流程降低了使用前置条件。事务、修订号、回收站和备份都是成熟技术；本项目的工程价值是把这些机制落实到双窗口的实际操作中。故障恢复、强制中断和系统环境的未测边界仍按验收计划推进，不作“绝不丢数据”的承诺。

## 可用于项目介绍的简版

> 侧笺 · SideTask 面向学习和专注工作的任务查看场景，将边缘快捷小窗与完整管理控制台结合。用户可以在小窗内查看今日安排和截止日期、直接添加任务并完成勾选；两个窗口与两种任务视图共享同一份任务状态。项目将今日安排与截止时间分开表达，并结合可选展开模式、草稿保护、四套界面风格与本地恢复能力，让任务管理更贴近当前桌面操作。现已提供 Mac 和 Windows 内部试用包，正在完善平台交互和真实环境验收。

展示时可围绕一条有 DDL 的任务依次演示：加入今日、在小窗查看、移出今日后确认 DDL 保留、重新加入并完成、在控制台核对同一状态；再演示快速输入隐藏后重显与取消退出。Windows 外点差异应随演示说明，不用 Mac 的行为代替 Windows 结果。

## 后续怎样验证这些价值

优先补齐 Windows 真实外点行为及两平台原生矩阵，再通过实际使用检验设计价值：记录“查看下一项任务”“随手新增一项”“完成并回到原工作”的操作路径、耗时、误触和重新输入情况。此处是验证方向，尚无用户研究数据证明注意力切换减少了多少，不能写成效率提升百分比。

下一阶段不因“创新”增加 AI、云同步、任务树、重复任务或移动端范围。先把现有流程做完整、做顺手，并补齐签名分发与长期试用证据；具体责任和验收标准沿用[下一阶段分工](../delivery/NEXT_STAGE.md)。
