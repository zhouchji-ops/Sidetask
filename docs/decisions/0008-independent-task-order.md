# ADR-0008：三个任务列表独立排序

日期：2026-09-28。状态：采用。

## 决定

今日计划、全部任务和截止日期列表分别保存手动顺序。今日继续使用指定日期的 `Plan.sortOrder`；全部任务与截止日期分别在共享快照中保存 `taskOrder`、`deadlineOrder` 两份 Task ID 序列。顺序属于列表，不写入任务内容，不改变任务修订号、截止日期或其他日期的计划。

截止日期保留日期、优先级两种自动排序，并增加手动排序。用户可在自动排序下直接拖动；一次成功事务同时保存顺序并切换为手动模式。切回自动排序仍保留手动顺序，之后可以恢复。新出现且尚未排序的任务追加到已排序任务之后；完成、回收站或暂时取消截止日期的任务保留原排序槽位，恢复后沿用。

控制台开放三个列表；小窗开放今日和截止日期。搜索结果、此前未完成、已完成和回收站不提供拖动，避免将局部筛选结果误当作完整排序列表。今日原有上移、下移按钮保留；拖动把手支持 Alt + 上下方向键。

## 提交与交互

拖动期间只显示插入位置，松手后提交一次完整活动集合与开始拖动时的快照版本。Rust 校验集合完整、不重复、任务适用和版本一致，再通过共享任务服务事务保存并通知另一窗口。失败保留已提交顺序并显示错误；另一窗口更新、切换列表、失焦或 Esc 取消尚未提交的拖动。拖回原位置不写入。

使用 Pointer Events 实现同一列表内的插入排序，继续复用现有虚拟列表。拖动行保持挂载，靠近滚动边缘时自动滚动，不把当前已渲染的行当作完整任务集合。小窗使用既有交互锁，锁按拖动会话分配；迟到的原生请求不能取消新的手势，取消后也不能继续发起焦点请求。无新增第三方依赖。

## 数据边界

SQLite 升为 schema 6。旧 schema 1–5 先创建 `before-schema-6` 一致性备份，再事务更新版本标记，保留原快照和窗口偏好原文；缺失排序字段只在内存中补空，成功业务写入后进入新格式。旧程序会拒绝 schema 6，不能用旧版本直接打开升级后的库。

便携任务备份输出 v3，包含两份排序；继续读取 v1/v2，默认没有自定义全部/截止顺序。导入保留本机设置，因此查看导入的截止手动顺序时可能需要选择“手动排序”。这不引入账号或多端同步。
