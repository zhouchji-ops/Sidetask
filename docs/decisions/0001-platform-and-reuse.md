# ADR-0001：首版双平台与复用方式

- 日期：2026-09-24
- 状态：平台范围仍有效；实现顺序及自建选型由 [ADR-0003](0003-prototype-implementation.md) 更新。以下保留初始评估背景。

## 背景

用户明确要求第一版同时支持 Mac 和 Windows。核心交互要求是边缘悬停、离开收起、全程不越到邻屏，以及今日计划与 DDL 同源完成。候选项目有明显接近之处，但案头核查尚未发现完全吻合的实现。

## 已确定

- 产品形态是独立桌面小工具，常驻菜单栏/系统托盘。
- Mac 和 Windows 属于同一个首版交付范围；不能只完成 Mac 就标记 MVP 交付。
- 先定义产品行为、做复用评估与窗口 POC，再开展完整业务开发。
- 本阶段只生成文档和目录，不引入第三方源码，不把占位工程称为可运行应用。

## 候选选择

优先验证 Tauri 2 + React/TypeScript + Rust + SQLite，共享任务核心、分别实现系统窗口适配。SwiftUI 原生单平台方案不满足首版范围；需要时仍通过 AppKit 实现 Mac 窗口细节。

Todobar 是整体 fork 候选；Peekaboo 是 Mac 行为参考。不能仅看 README 支持多屏就省略边界实测，也不能把提醒时间当成 DDL。

## 决定复用的证据

- 两平台能构建/安装；声明与实际版本一致。
- 许可证及依赖归属可按计划复用。
- 窗口策略和统一任务模型能在清晰模块边界内修改。
- 预计改造和维护上游的成本小于从精简核心实现；有代码探查或 POC 依据，非口头估算。

如窗口生命周期和任务模型都需要全面替换，倾向自建小型核心，只借鉴交互原理。无论选哪条路径，都需要双平台 POC。
