# Rust 存储规模实测

2026-09-25，Apple M5 / 16 GiB / macOS 26.4.1。结论：100与1,000任务的Rust完成/新建中位数约14–18ms；10,000任务约65–66ms，已经存在明确的全量处理成本。当前结果支持小规模内部试用，不能据此宣布10,000条任务的双窗口UI流畅。

## 方法与范围

使用系统临时目录中的独立Rust release程序，直接引用当前仓库的domain/application/infrastructure源码；依赖版本从项目Cargo.lock读取并固定，离线编译。没有修改公共Rust、运行用户App或读取个人数据库。数据完全合成：每任务一条今日计划、138字节英文备注；无DDL、日期DDL、`Asia/Shanghai`精确DDL各约三分之一。100 / 1,000 / 10,000任务的初始snapshot分别约50 KiB / 501 KiB / 4.91 MiB。

数据库为临时文件，沿用真实实现的SQLite事务、`synchronous=FULL`、`fullfsync=ON`、提交基线比较与全部业务校验。完成操作预热3次后测31次；创建和JSON导出15次；SQLite一致性备份7次。计时包含服务结果构建和释放，不包含进程编译、初次建库、Tauri IPC、React渲染、OS窗口反馈。没有控制整机后台负载，也未测试磁盘冷缓存/节能模式。

首次完整测量发现100/1,000档导出在15次新建后执行，已在第二次完整测量把导出/SQLite备份移到新建前，保证表内导出对应准确任务数。以下取第二次结果；首次完成中位数13.09 / 17.00 / 64.35ms，数量级一致。

## 结果

单位：毫秒，单元格为**中位数 / p95**。7次或15次样本的p95接近最大值，只是本次观测值，不是稳定服务保证。

| 操作 | 100任务 | 1,000任务 | 10,000任务 |
| --- | ---: | ---: | ---: |
| TaskService 完成/撤销（真实SQLite文件） | 14.01 / 16.28 | 17.97 / 18.87 | 65.32 / 68.33 |
| TaskService JSON导出（含再次解析校验） | 0.66 / 1.76 | 2.62 / 3.12 | 23.51 / 24.39 |
| 完整SQLite安全备份（含校验与同步） | 19.60 / 21.83 | 18.99 / 19.20 | 57.39 / 61.19 |
| 新建任务 | 15.79 / 16.17 | 16.04 / 18.87 | 见容量边界说明 |

新建15次会分别从100增长至115、从1,000增长至1,015。另用7个独立数据库测**9,999→10,000**成功新建，中位66.31ms / 最大67.58ms。已经10,000任务时再创建按容量约束拒绝，中位12.76ms；不会写入第10,001条。

10,000档31次完成操作的最大值为97.17ms，不能只看中位数。临时内存SQLite对照中，完整TaskService完成/撤销中位数为0.78 / 3.80 / 39.14ms，表明10,000档有明显CPU/内存处理成本，延迟不全来自磁盘同步。

| Snapshot深拷贝 | 0.027 | 0.263 | 1.854 |

## 复审结论与优化顺序

当前一次TaskService mutation依次经过：`Snapshot::apply`验证原快照和新快照；便携备份容量编码；Repository再次验证新快照、编码SQL快照；事务内读取旧JSON、反序列化并再次验证；比较持久化基线；写入提交；构建返回快照。也就是约四次全量validate，以及多次全量拷贝/编码。10,000档单次validate约5.5ms，四次约22ms；这只是成本估计，不把孤立测量相加当作精确profile。

没有发现需要在本次打包前紧急削弱校验的性能阻断。100/1,000档服务延迟较小；但10,000条的约5MiB快照每个小操作都重写、传输和返回，后续持续使用会放大全量模型成本，尤其需要测前端列表和双窗口事件刷新。SQLite规范化仍应进入后续路线。

可独立验收的优化候选，尚未改代码：

1. **避免事务内重复解析未变化的JSON**：Repository已保留验证过的原始JSON基线，可在事务内做限长读取并先比较原始字节。完全相等时已知是之前验证过的数据；不相等仍拒绝陈旧写入。保留并发/损坏/失败回滚回归。
2. **便携备份序列化借用字段**：容量检查可以序列化借用的task/plan切片，减少一次深拷贝；保持同一导出格式与精确字节上限，不能改成近似大小估计。
3. **明确已验证状态边界**：若进一步减少重复领域验证，先建立只能由校验/合法命令构造的状态类型，再保留落盘/导入处严格校验。当前public Snapshot和平台直接保存入口不适合直接删校验。
4. **规范化事务与按需快照**：后续Task/Plan表让完成仅更新对应记录；配合界面列表虚拟化/按需返回，才能从根本上降低大数据操作成本。

本轮仅增加本性能记录，没有修改上述优化候选涉及的源码。Windows性能、真实WebView端到端响应、长时间能耗、导入上限附近的长备注数据仍未测。
