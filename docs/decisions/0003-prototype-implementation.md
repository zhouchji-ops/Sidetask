# ADR-0003：自建最小核心与双窗口交互原型

- 日期：2026-09-24
- 状态：Accepted（原型实现）；双平台发布资格尚未通过
- 承接：ADR-0001 / ADR-0002

## 背景与决定

用户在需求文档后明确授权开始实现，并要求以未来可发布的 UI 质量作为设计目标。先前“只做文档”“两平台 POC 通过后才写全部 UI”的顺序由本决定更新：并行实现可评审 UI、共享任务核心与窗口 POC，保留双平台验收门槛。

采用 Tauri 2 + React / TypeScript + Rust + SQLite 自建精简原型。Todobar 的悬停行为、向屏幕外隐藏策略、提醒/DDL 模型都需要替换；本项目同时需要完整控制台与单一任务服务。基于已记录的源码核查，选择直接实现所需核心，不维护整体 fork。尚未完成 Todobar 两平台实机比较，不把这项判断写成实测性能优势。未复制候选项目源码；实际包版本由 package-lock.json 和 Cargo.lock 固定。

## 原型范围与边界

- React：控制台、任务详情/新建、设置、今日/DDL 小窗与把手。
- Rust：领域校验、版本冲突、事务用例、SQLite Repository 和平台窗口协调。
- 三个原生窗口共用一份 Rust 状态与 SQLite；提交事件触发重新查询。
- SQLite schema 1 暂用一个 JSON snapshot 行，另存停靠位置；不是设计文档里的最终规范化表结构。
- 浏览器预览通过独立 localStorage / BroadcastChannel 适配器使用合成数据，不用于桌面正式存储，也不能验证系统窗口行为。
- 任务只有独立大任务，没有子任务字段。

## 后续门槛

Windows 实际构建/启动、双平台多屏及焦点矩阵仍需通过。正式发布前补齐时区固定语义、边界定时器、数据迁移/恢复、设置应用失败状态及原生未保存草稿处理。设计精致不代表已完成签名、公证、分发、长期试用或兼容性验收。
