# ADR-0005：保留身份的回收站与备份版本

日期：2026-09-25。状态：采用，实现已接入；原生及双平台验收进度见 [STATUS](../delivery/STATUS.md)。接续 [ADR-0004](0004-data-safety-and-fixed-deadlines.md)。

## 背景

独立任务已有完成和今日安排，但误建或取消的任务只能留在日常列表。用户要求继续完善功能与使用体验，本阶段采用可恢复移出，不引入新的任务树、取消状态、永久删除或后台清理。固定官方 GitHub 行为参考和许可见 [生命周期计划](../research/TASK_LIFECYCLE.md)，未复制第三方实现。

## 决定

1. Task 增一个可空 `deletedAt`，与完成字段独立。单项移入/恢复只更新该字段和修订号，保留 Task ID、内容、DDL、创建/完成时间和全部 DailyPlan。只允许控制台发起；小窗通过同一已提交快照同步过滤。
2. 日常投影、计数和全局搜索排除回收站；回收站独立搜索和恢复，保留全量 ID 索引以保护跨窗口草稿。恢复不自动加入今天、不撤销完成。无自动清空或永久删除。
3. SQLite 升为 schema3，保持现有 JSON snapshot；schema1/2 验证、备份成功后仅事务更新版本/身份，原 snapshot/placement 不重编码。这样旧程序明确拒绝新版本，避免不理解删除字段的旧程序继续写入。
4. 便携 JSON 独立升为 v2，完整保存回收站和全部计划；接受 v1/v2，v1 不允许非空删除字段。预览明确总任务及其中回收站数，整份恢复替换完整集合，保留设备设置并提高修订号，不与当前记录合并。
5. 保存草稿再移入是两个有失败反馈的提交。后一步只使用自己保存响应的 Task revision；并发改动冲突后不自动重试删除。恢复行消失不卸载脏详情，恢复后的导航读取当前草稿门禁。

## 影响与限制

回收站计入现有容量限制；隐藏记录不用于绕过容量，也不会静默丢弃。保留计划可能在其他任务重排后形成相同 sortOrder，沿用稳定顺序；不承诺恢复旧绝对行号。后续若需要永久删除、容量整理或规范化存储，应单独设计迁移、可恢复性与用户入口，不在当前改动内加入框架。

旧 App 拒绝 schema3 是兼容保护，不提供原地降级。用户可保留升级前 SQLite 副本；启动损坏恢复同时识别 before-schema-2、before-schema-3 和 safety-backup。详细恢复操作见 [DATA_RECOVERY](../engineering/DATA_RECOVERY.md)。自动化通过不替代真实 App 升级、窗口或安装验收。
